# RAG_product


# Архитектура решения 
## Общая схема компонентов 

   * Search API (интернет-поиск) - StackExchange/Search API для поиска вопросов по StackOverFlow
   * FAISS(Векторная база) - для хэширования только полезных найденных ответов со StackOverFlow
   * LLM(ollama, Mistral AI, GPT-5)- модель, которую будем задавать системе для генерации ответа
   * LangChain - Библиотека, которую будем использовать для построения приложения(RAG) на основе LLM
   * Tg/Chatbot - для фронтенда чтобы можно было показывать результат работы


## Потока данных
### Шаг 1. Вход: вопрос / код / stacktrace
   *  На вход система получает текст вопроса, фрагмент кода или контекст, затем ассистент будет использовать базу на основе ответов поиска через StackExchange/Search API со Stack Overflow/Хабр и генерировать релевантные решения, реконмендации или рабочее решение.
   * Система распознаёт язык кода, выделяет:
      * Kлючевые слова и исключения 
      * Тип проблемы (сетевая, логическая, синтаксическая);
   
   ### Шаг 2. Формирование поискового запроса (Query Building)
* Пример:
   * site:stackoverflow.com "requests.exceptions.ReadTimeout" Python

   ### Шаг 3. Живый поиск (через интернет)
    * Система запрашивает Google/Bing/StackExchange API и получает:
         * заголовок,
         * URL,
         * сниппет,
         * дату,
         * рейтинг.

   ### Шаг 4. Загрузка и разбор страниц
   * Для топ 5–10 найденных URL:
      * скачать HTML,
      * извлечь текст,
   * выделить:
      * вопрос,
      * accepted answer,
      * код,
      * комментарии.

 ### Шаг 5. Эмбеддинг + Reranking найденных решений
   * разбить текст на чанки,
   * эмбеддинги (на лету),
   * reranker выбирает top-3 наиболее подходящих решения.

   ### Шаг 6. Генерация финального ответа

   * LLM получает:

      * вопрос пользователя,
      * 3–5 лучших найденных фрагментов,
      * ссылки,
      * примеры кода.

   ### Шаг 7. Отображение результата пользователю

   * Показывается:
      * текст ответа,
      * код с подсветкой,
      * ссылки на оригинальные статьи,
      * кнопки «Помогло / Не помогло».

   ### Шаг 8. Фидбек
   * Если пользователь нажал «Помогло»:
      * документ сохраняется в локальный векторный кэш (Faiss/Qdrant),
      * повышается рейтинг данного URL.
   * Если «Не помогло»:
      * не кэшируется,
      * система ищет альтернативные источники.
