# RAG_product


# Архитектура решения 
### 1. Общая схема компонентов 

   * Search API (интернет-поиск) - StackExchange/Search API для поиска вопросов по StackOverFlow
   * SO_search_API - для поиска вопросов по тексту по StackOverFlow
   * SO_answers_API - для поиска ответов на вопросы по найденным IDS вопросов
   * FAISS/Qdrant(Векторная база) - для хэширования только полезных найденных ответов со StackOverFlow
   * LLM(ollama, Mistral AI, GPT-5)- модель, которую будем задавать системе для генерации ответа
   * LangChain - Библиотека, которую будем использовать для построения приложения(RAG) на основе LLM
   * Tg/Chatbot - для фронтенда чтобы можно было показывать результат работы

### 2. Инструменты (Tools/Retrieval)

Это внешние API, которые Оркестратор использует для сбора актуальной информации.

| Компонент | Роль | Примечание |
| :--- | :--- | :--- |
| **WebSearch API** | **Общий Поиск.** Используется для поиска свежей информации, документации, или вопросов на любых других ресурсах, кроме SO (например, GitHub, блоги). | Дублирует SO\_search\_API, если запрос не строго SO-специфичен. |
| **SO\_search\_API** | **Поиск Вопросов.** Находит идентификаторы (IDs) релевантных вопросов на Stack Overflow по ключевым словам из запроса пользователя. | |
| **SO\_answers\_API** | **Получение Контента.** Использует найденные IDs, чтобы извлечь текст самого вопроса и всех ответов (включая комментарии и код). | Это этап **Извлечения (Retrieval)** для RAG. |


### 3. Генерация и Верификация

| Компонент | Роль |
| :--- | :--- |
| **TODO LocalLLM (Векторы/IFы)** | **Выбор Лучшего Примера.** Получает все ответы с SO (включая принятый ответ и голоса). Использует логику на основе **встроенных правил (IFs)**, **встраиваний (Embeddings)**, или **небольшой LLM** для ранжирования/выбора *самого лучшего, самого высокого проголосованного, или самого релевантного* кода/ответа для использования в качестве контекста. |
| **LLM (ollama, Mistral AI, GPT-5)** | **Генератор Ответа.** Получает **изначальный запрос** пользователя + **контекст (извлеченный код/ответы SO)**. Задача этой модели — сгенерировать понятный, структурированный, итоговый ответ на основе предоставленной информации. |
| **TODO Другая ЛЛМ (например Codestral)** | **Проверка Кода (Code Verification).** Эта модель (или набор скриптов) получает извлеченный код и проверяет его на: 1. Синтаксические ошибки. 2. Логическую корректность (если возможно, через выполнение в изолированной среде). 3. Затем возвращает результат проверки Оркестратору. |


### 4. Схема Потока Запроса (Workflow)
  * 1. Пользователь отправляет запрос через Tg/Chatbot.

  * 2. Бэкэнд получает запрос и передает его Оркестратору (Local LLM).

  * 3. Оркестратор анализирует: "Это технический вопрос, нужен поиск".

  * 4. Оркестратор вызывает:

       * SO_search_API и WebSearch API.

  * 5. Оркестратор получает IDs/ссылки и вызывает SO_answers_API, извлекая сырой текст ответов.

  * 6. Сырой текст отправляется в LocalLLM (Выбор Примера), которая выбирает наилучший код/фрагмент.

  * 7. Лучший код отправляется в Codestral (Проверка Кода).

  * 8. Оркестратор собирает все данные: [Запрос] + [Лучший SO Ответ] + [Результат Проверки Кода].

  * 9. Оркестратор формирует финальный промпт и отправляет его в Основную LLM (Mistral/GPT-5).

  * 10. Основная LLM генерирует окончательный ответ.

  * 11. Ответ возвращается через Бэкэнд к Пользователю в Tg/Chatbot.

  # User Cases
## Приоритет 1 (MVP)	
1. Первичная диагностика	
* "Я пользователь, у меня проблема с кодом, я отправляю текст ошибки и ту часть кода, которая её вызывает. 
* Я хочу получить ответ: 
- Я хочу получить ответ:
   1. В чем причина ошибки
   2. Как её исправить
   3. Пример исправленного кода
      - Дополнительно: распознавание типа ошибки (синтаксис, runtime, логика)
> Комментарии по архитектуре:
> - Извлечение релевантного контекста из кода
> - Поиск аналогичных ошибок в базе знаний"

2. Итеративное уточнение  
* "Я пользователь, у меня проблема с кодом, я уже отправил текст ошибки и ту часть кода, которая её вызывает.  
Получил от агента первое предположение, проверил и оно не работает.  
* Я хочу:  
   1. отправить только добавленную информацию (например, "попробовал твое решение - не помогло")  
   2. предыдущие выводы повторно не отправлять, но чтобы они учитывались в контексте  
   3. получить новые указания как в п. 1  
> Комментарии по архитектуре:  
> - Сохранение контекста диалога  
> - Понимание, что это продолжение предыдущего запроса  
> - Эскалация сложности диагностики  

3. Уточняющие вопросы  
* "Я пользователь, у меня проблема с кодом, я уже отправил текст ошибки и ту часть кода, которая её вызывает.  
Получил от агента первое предположение, но у меня есть по нему вопросы или новые предложения.  
* Я хочу:  
   1. отправить короткий вопрос или предложение ("а почему именно так?", "можно ли сделать через X?")  
   2. не отправлять повторно всю информацию, но чтобы она была учтена при ответе  
   3. получить развернутое объяснение или альтернативные варианты  
> Комментарии по архитектуре:  
> - Понимание интенции уточняющего вопроса  
> - Связь с предыдущим контекстом  
> - Способность объяснять "почему", а не только "как"  

## Приоритет 2 (развитие продукта)

4. Множественные попытки  
* "Я пользователь, уже получил несколько итераций ответов от агента, но проблема не решена.  
* Я хочу:  
   1. получить эскалацию - переход к более глубокому анализу  
   2. альтернативные подходы к решению  
   3. диагностические шаги для выявления корневой причины  
> Комментарии по архитектуре:  
> - Отслеживание количества итераций  
> - Автоматическая эскалация сложности анализа  
> - Генерация диагностических сценариев  

5. Неполная информация  
* "Я пользователь, не уверен какая именно информация нужна агенту для решения проблемы.  
* Я отправляю:  
   1. только текст ошибки без кода  
   2. только код без описания проблемы  
   3. неполный фрагмент кода  
* Я хочу чтобы агент:  
   4. понял чего не хватает  
   5. запросил конкретную дополнительную информацию  
   6. объяснил зачем она нужна  
> Комментарии по архитектуре:  
> - Анализ достаточности входных данных  
> - Генерация целевых вопросов для уточнения  
> - Объяснительная способность ("мне нужен X, потому что Y")  

6. Смена контекста/темы  
* "Я пользователь, уже общался с агентом по одной проблеме, но теперь хочу обсудить другую.  
* Я отправляю:  
   1. совершенно новый вопрос без отсылки к предыдущему  
   2. явный индикатор смены темы ("теперь по другой проблеме...")  
* Я хочу:  
   3. чтобы агент понял что это новая тема  
   4. не тащил старый контекст в новый запрос  
   5. но сохранил историю на случай если я вернусь к старой проблеме  
> Комментарии по архитектуре:  
> - Детекция смены контекста  
> - Управление сессиями/топиками  
> - Сохранение и восстановление контекста  

7. Верификация решения  
* "Я пользователь, получил от агента решение и внедрил его.  
* Я хочу:  
   1. сообщить что решение сработало ("спасибо, помогло!")  
   2. получить дополнительные рекомендации по улучшению  
   3. узнать о потенциальных edge cases  
   4. получить связанные best practices  
> Комментарии по архитектуре:  
> - Распознавание позитивного фидбека  
> - Генерация продвинутых рекомендаций  
> - Поиск связанных материалов для углубления  

8. Сравнение подходов  
* "Я пользователь, рассматриваю несколько вариантов решения.  
* Я отправляю:  
   1. несколько вариантов кода или подходов  
   2. вопрос "какой вариант лучше и почему?"  
* Я хочу:  
   3. сравнительный анализ производительности, читаемости, поддерживаемости  
   4. рекомендацию с обоснованием  
   5. примеры использования каждого подхода  
> Комментарии по архитектуре:  
> - Сравнительный анализ кода/архитектур  
> - Понимание критериев оценки (перфоманс, readability и т.д.)  
> - Генерация обоснованных рекомендаций  

9. Обучение и объяснение  
* "Я пользователь, хочу не просто решение, а понять концепцию.  
* Я отправляю:  
   1. вопрос "объясни как работает X"  
   2. "в чем разница между Y и Z"  
* Я хочу:  
   3. структурированное объяснение с примерами  
   4. аналогии для сложных концепций  
   5. ссылки на дополнительные материалы  
> Комментарии по архитектуре:  
> - Генерация обучающего контента  
> - Использование аналогий и примеров  
> - Интеграция с учебными материалами  

## Приоритет 3 (стратегическое развитие)
10. Экстренная помощь  
* "Я пользователь, у меня критическая проблема в production.  
* Я отправляю:  
   1. явные индикаторы срочности ("срочно!", "production down")  
   2. минимальную но критически важную информацию  
* Я хочу:  
   3. максимально быстрый ответ  
   4. immediate actionable решения  
   5. временные фиксы и долгосрочные решения  
> Комментарии по архитектуре:  
> - Приоритизация запросов  
> - Распознавание срочности  
> - Генерация quick fixes + permanent solutions  

11. Архитектурный запрос  
* "Я пользователь, планирую архитектуру системы.  
* Я отправляю:  
   1. описание требований и constraints  
   2. вопросы о масштабируемости, безопасности, производительности  
* Я хочу:  
   3. рекомендации по архитектуре  
   4. анализ trade-offs разных подходов  
   5. примеры успешных implementations  
> Комментарии по архитектуре:  
> - Анализ архитектурных паттернов  
> - Понимание системных требований  
> - Генерация архитектурных рекомендаций  

12. Отладка сложных систем  
* "Я пользователь, имею распределенную систему с множеством компонентов.  
Проблема проявляется только в определенных условиях.  
* Я отправляю:  
   1. логи из разных компонентов  
   2. описание workflow  
   3. условия когда проблема возникает  
* Я хочу:  
   4. корреляцию событий в разных логах  
   5. гипотезы о корневой причине  
   6. план диагностики  
> Комментарии по архитектуре:  
> - Анализ распределенных логов  
> - Корреляция событий  
> - Генерация диагностических сценариев
